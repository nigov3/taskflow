# TaskFlow — доска задач с правами доступа

## Что умеет

- **Два режима работы** (переключаются автоматически):
  - **Локальный** — всё хранится в вашем браузере. Владелец один, вход по имени и паролю. Подходит для личного использования.
  - **Командный (Supabase)** — настоящая серверная авторизация: каждый сотрудник входит по email/паролю, задачи и команда общие, изменения видны всем в реальном времени. Права проверяются **на сервере**, обойти их через DevTools нельзя.
- **Роли:**
  - 🛡️ `Владелец` (вы) — всё: задачи, сотрудники, роли, назначение других владельцев.
  - ✏️ `Редактор` — может создавать и менять задачи.
  - 👤 `Сотрудник` — только просмотр доски и команды.

## Как включить командный режим (5 минут, без программирования)

1. Зарегистрируйтесь бесплатно на [supabase.com](https://supabase.com) и создайте проект.
2. Откройте в проекте вкладку **SQL Editor → New query**, вставьте целиком содержимое файла [`supabase-schema.sql`](./supabase-schema.sql) и нажмите **Run**. Это создаст таблицы и правила доступа.
3. Скопируйте из Supabase два значения (**Settings → API**: `Project URL` и `anon public key`).
4. В файле `index.html` замените две строки в начале скрипта:
   ```js
   const SUPABASE_URL = 'XXX';   // → 'https://ваш-проект.supabase.co'
   const SUPABASE_KEY = 'XXX';   // → ваш anon key
   ```
5. Опубликуйте сайт (GitHub Pages / Netlify / любой хостинг статических страниц) и откройте его.
6. **Зарегистрируйтесь первым** — этот аккаунт автоматически станет владельцем. Остальных приглашайте через «Регистрацию»: они получат роль «Сотрудник», а права им выдаёте только вы в панели «👥 Команда → Доступ к приложению».

> Совет: в Supabase (Authentication → Providers) можно отключить обязательное подтверждение email, чтобы сотрудникам не нужно было переходить по ссылке.

## Безопасность

- Пароли никогда не хранятся в открытом виде (в локальном режиме — SHA-256 с уникальной солью; в Supabase — bcrypt на сервере).
- В командном режиме все правила (кто может писать в базу, кто может менять роли) исполняет сервер Postgres через Row Level Security. Подделать «я владелец» из браузера невозможно.
- `anon public key` безопасно публиковать в коде — доступ ограничивают RLS-политики. **Service role key нигде публиковать нельзя.**
